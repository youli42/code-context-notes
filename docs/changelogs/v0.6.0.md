# Changelog - Version 0.6.0

## [0.6.0] - 2026-11-09

Notes became portable: `**File:**` now stores a workspace-relative path, legacy notes can be migrated in bulk, and any note can be re-attached to a different code file.

### Added

- **Re-attach Note to Another File…** — right-click a note in the **Code Notes** sidebar (or run the command with the note's line under the cursor) and pick the file it should now annotate. The note id, content and full history are kept; the annotated code is re-located in the target file by content hash, so it lands on the right lines instead of line 1. When the code isn't in the target file the old range is clamped and the original hash is kept, so the note still tracks what it was written about.
- **Migrate Notes to Relative Paths** — one-shot command that rewrites every legacy note whose stored path is absolute *and* inside the workspace. Notes that are already relative, or that point outside the workspace, are left untouched; the result message reports how many files changed.

### Changed

- New and edited notes store `**File:**` relative to the workspace root, using `/` separators, so a committed `.code-notes/` keeps working after the repository is cloned to another directory or machine.
- Paths outside the workspace are still stored absolute — a `..`-relative path would be no more portable.
- Reading is backward compatible: a pre-0.6 note with an absolute `**File:**` loads exactly as before and is rewritten in relative form the next time it is saved.
- `INDEX.json` and `AGENTS.md` were already workspace-relative; they are unchanged.

### Fixed

- The `ExportWriter` failure-path test used a hard-coded POSIX path (`/this/path/does/not/exist/anywhere`). On Windows that resolves to a creatable relative path, so `mkdir` succeeded, the error branch was never reached and the test failed (and left `F:\this\…` behind). It now uses a regular file as the workspace root, which fails with `ENOTDIR` on every platform.

### Testing

- Core: 180 tests (11 new) — relative serialization, legacy absolute-path round trip, outside-workspace fallback, bulk migration counts, and rebind anchoring/clamping/deleted/agent-writer cases.
- MCP: 76 tests, unchanged and green (in-memory `Note.filePath` is still absolute, so tool matching is unaffected).
- Extension: 24 unit tests green; `compile:tsc` clean.

### Technical

- `StorageManager.toStoredPath()` / `fromStoredPath()` are the only places that translate between the on-disk representation and the absolute path the `Note` type promises. `finalizeNote()` is the single load-side hook.
- `NoteManager.rebindNote()` is human-only (like `updateNoteMetadata`), re-anchors via `ContentHashTracker.findContentByHash()`, and moves the note between per-file caches with `moveNoteInCache()`.
- Compatibility note: a pre-0.6 extension or MCP server reads a relative `**File:**` verbatim and will not match it to a file, so upgrade the extension and the MCP server together.
