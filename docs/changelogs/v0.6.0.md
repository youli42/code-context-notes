# Changelog - Version 0.6.0

## [0.6.0] - 2026-11-13

Notes became portable: `**File:**` now stores a workspace-relative path, legacy notes can be migrated in bulk, and any note can be re-attached to a different code file.

### Added

- **Re-attach Note to Another File…** — right-click a note in the **Code Notes** sidebar (or run the command with the note's line under the cursor) and pick the file it should now annotate. The note id, content and full history are kept; the annotated code is re-located in the target file by content hash, so it lands on the right lines instead of line 1. When the code isn't in the target file the old range is clamped and the original hash is kept, so the note still tracks what it was written about.
- **Re-attach All Notes in This File…** — right-click a file group in the sidebar to point *every* note attached to that file at another file in one go. This is the batch path for lost references (the old file was renamed, moved, or deleted): each note is re-anchored by content hash independently, and the result message reports how many were found and how many kept their old line.
- **Migrate Notes to Relative Paths** — one-shot command that rewrites every legacy note whose stored path is absolute *and* inside the workspace. Notes that are already relative, or that point outside the workspace, are left untouched; the result message reports how many files changed.

- **Edit Note at Cursor (`Ctrl+Alt+A` / `Cmd+Alt+A`)** — opens the note under the cursor in edit mode and moves the caret into the comment editor, so a quick edit is one keystroke and no mouse. The same focus behaviour now applies when edit mode is opened from the comment toolbar or the sidebar: the thread is collapsed and re-expanded, which is the path VS Code uses to focus a comment that is in edit mode.

### Changed

- New and edited notes store `**File:**` relative to the workspace root, using `/` separators, so a committed `.code-notes/` keeps working after the repository is cloned to another directory or machine.
- Paths outside the workspace are still stored absolute — a `..`-relative path would be no more portable.
- **`.code-notes/` now appears with the first note.** Activating the extension no longer creates the folder, export regeneration returns `skipped` instead of writing empty `INDEX.json`/`AGENTS.md` into a workspace without notes, and changing an agent setting no longer creates `config.json` there either. The folder — and its self-ignoring `.gitignore` — still appears the moment you save a note.
- Reading is backward compatible: a pre-0.6 note with an absolute `**File:**` loads exactly as before and is rewritten in relative form the next time it is saved.
- `INDEX.json` and `AGENTS.md` were already workspace-relative; they are unchanged.

### Fixed

- **Add Note from the keyboard now focuses the note input.** A comment thread created through the Comments API keeps keyboard focus in the code editor, so after `Ctrl+Alt+N` the next keystroke went into the file and the note had to be clicked first — unlike the gutter **+** button, which uses VS Code's own add-comment flow. When the cursor line has no note, the shortcut now runs that same VS Code action, which creates the thread and puts the caret in the note input. Adding a *second* note to a line that already has one still uses the extension's own editor (VS Code's action would just toggle the existing thread).

- Note binding compared file paths with exact string equality. On Windows the filesystem is case-insensitive, so a legacy note storing `f:\Work\app.ts` never matched `F:\Work\app.ts` — its CodeLens, comment thread and commands silently found nothing and looked like they did nothing. Binding now compares case-insensitively on Windows (`pathsEqual`), so differently-cased legacy paths resolve again.
- The `ExportWriter` failure-path test used a hard-coded POSIX path (`/this/path/does/not/exist/anywhere`). On Windows that resolves to a creatable relative path, so `mkdir` succeeded, the error branch was never reached and the test failed (and left `F:\this\…` behind). It now uses a regular file as the workspace root, which fails with `ENOTDIR` on every platform.

### Testing

- Core: 188 tests (19 new) — relative serialization, legacy absolute-path round trip, Windows case-insensitive binding, outside-workspace fallback, bulk path migration, single and batch rebind (anchored, unanchored, deleted, agent-writer, empty group), and exact-only cross-file anchoring.
- MCP: 76 tests, unchanged and green (in-memory `Note.filePath` is still absolute, so tool matching is unaffected).
- Extension: 24 unit tests green; `compile:tsc` clean.

### Technical

- `StorageManager.toStoredPath()` / `fromStoredPath()` are the only places that translate between the on-disk representation and the absolute path the `Note` type promises. `finalizeNote()` is the single load-side hook.
- `NoteManager.rebindNote()` is human-only (like `updateNoteMetadata`), re-anchors via the new exact-only `ContentHashTracker.findExactContentByHash()` (the fuzzy fallback is same-file only: it compares the document against itself and would match anything across files), and moves the note between per-file caches with `moveNoteInCache()`.
- Compatibility note: a pre-0.6 extension or MCP server reads a relative `**File:**` verbatim and will not match it to a file, so upgrade the extension and the MCP server together.
